## A
- **API:** - A Git API, such as the GitHub API, is a set of rules and tools that allows developers to programmatically interact with and manage Git repositories and related services like issues, pull requests, and user data.


## B
- **Branch** - A Git branch is a lightweight, movable pointer to a specific commit, representing an independent line of development within a repository.


## C
- **Commit** - A Git commit is a snapshot of the project at a specific point in time, recording the staged changes in the repository's history along with a descriptive message.


## F
- **Fork** - A Git fork is a personal copy of an entire Git repository, typically hosted on a platform like GitHub, that allows you to make changes and experiment without affecting the original project.


- **Fetch** - Git fetch downloads commits, files, and refs from a remote repository into your local repository without merging them into your current working branch.


## M
- **Merge** - Git merge is the process of integrating independent lines of development from different branches into a single, unified branch, often creating a new merge commit to record the combination of histories.
- **Merge Conflict** -A Git merge conflict occurs when Git cannot automatically reconcile differing changes made to the same lines of code or files across two branches being merged, requiring manual intervention to resolve the discrepancies.


## P
- **Pull Request** - A Git pull request is a formal proposal to integrate changes from one branch into another, typically used for code review and collaboration before merging them into the main codebase.
